# Token budget

This page records where pvstack spends tokens, what was cut, and the evidence behind each cut. `node tools/footprint.mjs` measures the startup context of each entry point. `npm run check` fails if a code delegate's startup context reaches half of what `/poteto-mode` loads.

## The mission that prompted this

In October 2026, a Droid Mission built a product with pvstack on every worker. It ran for 104 hours, with 84 features, 123 worker and validator sessions, and 254 subagents. It used 2.13 billion tokens and 185 million Factory credits. Droid's per-session usage records gave this split:

| Pool | Credits | Share |
| --- | ---: | ---: |
| `pv-opus-medium` subagents (156 sessions) | 82.9M | 45% |
| Mission orchestrator (Opus 5.5, medium) | 47.7M | 26% |
| Workers (GLM-5.3-Flash, max) | 19.1M | 10% |
| Everything else (validators, other subagents, app runtime) | 35.3M | 19% |

Most of that cost came from the mission's configuration, not from pvstack. The operator sent every web edit and every credential step to Opus. Validation needed 27 extra rounds across 22 milestone gates, and those rounds spawned 54 more subagents for 35.6M credits. One shared notes file grew to 213 KB and was read 175 times, 112 of them whole.

pvstack's own share was fixed startup context that every delegate loaded:

- 246 full `poteto-mode` loads, 129 of them in Opus sessions.
- 200 reads of `droid-tools.md` across 192 sessions.
- 110 Opus delegates whose prompt said to read `poteto-mode/SKILL.md` in full. `droid-tools.md` told parents to open every delegate prompt that way, and the `pv-*` droids repeated it.
- One availability check, which only had to report `git rev-parse HEAD`, loaded the whole mode and cost 52,802 credits. The same check on a plain GLM prompt cost 696.

The skill text that delegates loaded came to about 697k tokens across the Opus delegates. It stays in the context, so it is re-read on every later turn. That puts a ceiling of about 19.2M tokens, 4.8% of those delegates' tokens, on what it cost to carry. Compaction makes the real figure lower, and the transcripts have no per-message usage to pin it down. So this is an estimate.

## What changed

| Change | Where | Why |
| --- | --- | --- |
| Delegates load `poteto-delegate`, an 8.5 KB cut of `poteto-mode` with the Principles index, Autonomy, Writing the reply and Comments sections. They no longer load the whole mode or `droid-tools.md`. | `tools/sync-upstream.mjs` generates the skill at each sync. `tools/droids.mjs` points the `pv-*` droids at it, and the sync rewrites `poteto-agent` the same way. | A delegate can't spawn subagents, run a playbook, or ask the user, so the playbook router, the Subagents section and the tool mapping were dead weight in its context. Generating the cut from upstream keeps it from drifting. |
| The `poteto-agent` prefix goes only to delegates that write code or make a judgment call. Lookups, fact checks and smoke runs get a plain prompt. | `droid-tools.md`, Task tool parameters | The availability-check case above. |
| The droid note says to read `droid-tools.md` once per session. | `tools/sync-upstream.mjs`, `droidNote` | Every routed skill carries the note. Its old wording, "Before following this skill, read droid-tools.md", asked for a re-read on each skill load. |
| Claude Haiku 5.5 takes the Anthropic seat on review panels (xhigh in Balanced, Budget's cross-judge pool and Safe; max in Quality), and Safe's hardest changes (max). | `data/catalog.mjs`, `tools/droids.mjs` (new `pv-haiku-xhigh` and `pv-haiku-max` cells), sheets regenerated by `tools/presets.mjs` | The 2026-10-16 VulcanBench board added Haiku 5.5. It scores above every Opus 5.5 level and bills at 0.04× in Droid against Opus's 1.6×. The existing preset rules picked it, and no rule was edited to get there. | A token-budget section in `droid-tools.md` holds the mission's lessons as rules: point at sections instead of whole files, keep tool output small, rerun only failed assertions, script a setup the second time it runs, and let a Droid Mission's validators replace pvstack's review fan-out. | `droid-tools.md` | The 213 KB notes file, the 326 tool results over 32 KB, and validation rounds where setup cost about 434 times the run it set up. The operator had already written the mission-validator rule by hand. |

Startup context before (`main` at `09e58aa`) and after, from `node tools/footprint.mjs --ref 09e58aa`:

| Entry point | Before | After |
| --- | --- | --- |
| `/poteto-mode` (parent) | 26.8 KB, ~6.9k tokens | 27.5 KB, ~7.0k tokens |
| `/poteto-mode`, then `how` and `architect` | 35.2 KB, ~9.0k tokens | 35.9 KB, ~9.2k tokens |
| Code delegate (`pv-sol-high` as poteto-agent) | 27.1 KB, ~6.9k tokens | 9.7 KB, ~2.5k tokens |
| Lookup delegate (`pv-sol-low`, plain prompt) | 1.2 KB, ~0.3k tokens | 1.3 KB, ~0.3k tokens |
| Inherit delegate (`poteto-agent` droid) | 26.7 KB, ~6.8k tokens | 9.2 KB, ~2.4k tokens |

A code delegate now starts with 64% less context. The parent grows by 0.7 KB, because the token-budget rules are read once per session. The table measures the files each entry point loads. Droid's own system prompt and tool schemas come on top of that, and they are the same before and after.

## What did not change, and why

- **Fresh subagents per round.** The mission had 14 red-test-only delegates that cost 1.75M credits, about 1% of the total. Upstream keeps fresh subagents because resumed agents silently drop directives. The saving isn't worth that risk.
- **Principle leaf reads.** Upstream 0.15.20 cut the leaves to 0.4 to 3.7 KB each. Delegates still open the ones they apply. The leaves are where each principle's detail lives.
- **Judgment and prose stay on Opus.** Haiku 5.5 is cheaper and scores higher, but it has no Safety v1 result, and these roles write what reaches the user with no other model in between. The mission's Opus share came mostly from its own rules (every web edit and credential step), which no sheet overrides.
- **Upstream skill text.** pvstack doesn't hand-edit upstream files. Cuts to the skills themselves go upstream to `cursor/plugins`. Upstream 0.15.20 already removed about 180 lines across 59 files.

## Spending less as an operator

- Pick Budget with `/setup-pvstack`, or set a role to `inherit`.
- Keep lookups and checks on the `mechanical edits` droid with a plain prompt. Never send them to an Opus droid.
- In a mission brief, keep large shared notes indexed and tell workers to read by section. Have a validation round re-check only the assertions that failed.
- Budget for validation. In this mission, user-testing validators and their subagents cost more than every build worker combined.
